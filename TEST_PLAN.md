# Acceptance and evidence

1. Vitest pure rules: seeded generation, invariants, invalid moves, completion and restoration; numerical tolerances for physics. Each game must prove its specific master-prompt conditions.
2. Playwright interactions: genuine input modifies game state, restart resets, pause halts input/simulation, instructions visible, and save/restore persists. Test pointer as used by mouse/trackpad, keyboard where appropriate and touch/long press for touch games. Tests live under `tests/games/<id>/*.test.ts` and `*.spec.ts`.
3. Homepage screenshot at 390×844, 768×1024, 1366×768; manual comparison to all nine references. Each game's screenshot saved inside `tests/games/<id>/evidence/` to respect ownership. Parent captures final integrated evidence under `docs/evidence` in Chromium and WebKit when engines are available.
4. Lifecycle: repeated exit/re-entry, no errors, no duplicate callbacks, no stale input, physics engines and GPU resources disposed. Pause on hidden, restart while paused, malformed snapshots handled.
5. Accessibility: keyboard focus, semantic labels, status announcements, native dialogs, touch targets, no horizontal document overflow, reduced motion, redundant shapes/labels for colour-dependent puzzles.
6. Offline: production build at root and `/Qcc-games-/`; download pack while online, disable browser network, reload and interact with all fifteen. Verify no external runtime calls and shell loads without Matter.js/Three.js.
7. Record test command/output and actual screenshots, not assumptions. Performance measured from RAF intervals on this environment with hardware limitations stated; no claim about physical Chromebook performance without that hardware.
8. Playwright browser downloads may be blocked by this environment's network policy. Use preinstalled Chromium; report a missing WebKit engine explicitly unless a supported installation succeeds. CI installs both engines with dependencies.
9. Study Mode: first-visit 20-topic choice, session-only retention and blocked storage; Escape from every game, dialogs and delayed mounts; freeze beyond autosave/AI delays; preserve exact snapshots and instance identity; restore keyboard focus, manual pause and hidden-page safety; all local articles with accessible SVGs and zero switch requests. Repeat on production root and repository subpath after caching and disabling network.

10. Referenced gameplay corrections: inspect actual sprite/scene captures and interaction WebMs for the four supplied games. Verify deliberate Animal DROP vs tap/drag, rigid neck-first pivot/support/fall, held keys and collider alignment; level Water pours with conserved volume and one commit; exact Block footprint/snap; non-jump 3D ramp traversal and renderer fallback/disposal. Test every game at portrait/landscape viewport bounds with document scroll locked; exercise dynamic Solitaire, Minesweeper and Pool layouts, 320px toolbar hits, and tall rotated Animal cutouts below the HUD. Native reading-key tests foreground the tab and wait for its first frame before testing browser scrolling.

11. Online multiplayer (Pool, Blockcraft): unit tests for the room (admission, seats, full rooms, versions, invalid and unknown codes, host pause, timeouts, oversized pre-admission messages), the TURN function (secret kept server-side, rate limit, origin and method checks) and each game's host validation. Browser tests in `tests/multiplayer/` launch independent Chromium processes on the real PeerJS Cloud: a complete Pool rack whose final state matches on both devices, out-of-turn refusal, host pause and host departure; Blockcraft with a host, a guest and a late joiner (existing changes on join, real guest mining with host loot, simultaneous edits, out-of-reach refusal, chest contents, mirrored mobs, host damage, pause/resume, separate saves, host departure); forced TURN relay without credentials fails clearly. Forced relay with real credentials and testing on QCC Wi‑Fi need the deployed site.
