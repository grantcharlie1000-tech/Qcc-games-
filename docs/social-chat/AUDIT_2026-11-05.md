## PR #125 CI follow-up

- The reviewed baseline Following-feed fix waits for the current account’s already-started follow/unfollow writes before loading authoritative posts. It preserves cancellation, identity isolation and the mutation’s original error. Discover, mentions, profile requests and uploads stay independent. Its photo-upload regression uses an explicit pending-response gate instead of a fixed delay. The audit’s numeric-counter assertions remain intact.
- The Social shortcuts test now waits for the initialized feed and New post control before pressing `?`, then checks focus restoration.
- The leaderboard test waits for native scrolling to settle before reversing direction. Shift+Space must move backward rather than land at an exact pixel; Home/End boundaries, focus, game-state and navigation checks remain.
- Initial WebKit `after-chat-message-actions` and `after-chat-sent-wrapped-message` images showed no menu and no wrapped message respectively, despite passing tests. The new capture guard waits for target/ancestor entry motion to settle and requires the authoritative message or open menu. It checks the same DOM node immediately after capture, without retries, and only writes/attaches the PNG if both checks pass. This is evidence hardening, not a verified compositor fix. Fresh browser execution and image inspection are required.
- Local focused checks pass 43 tests in five files, including 12 Following client tests and four capture-helper guards. The helper guards failed before their implementation and pass afterward. Browser discovery collects 130 cases in seven files when the existing Social browser suite is included. Collection is not execution; the earlier aggregate result above is not a full rerun of this follow-up.
- Final follow-up production build (including TypeScript) passed with a 2 GiB Node heap; all three noindex checks passed. Only the existing Vite large-chunk warnings remain. No local browser launch or full unit-suite rerun was performed for this follow-up.
