# Offline Mini-game Arcade Implementation Plan

> For agentic workers: use the installed parallel-agent workflow and GAME_AGENT_GUIDE.md for the twelve isolated specialists. Parent integrates and verifies one commit at a time.

**Goal:** A faithful portrait-card arcade with exactly twelve playable, offline-capable games.

**Architecture:** Static Vite/TypeScript shell, frozen module lifecycle contract, separate deterministic engines, lazy game chunks. Matter.js for the two stacking games, Three.js only for Ball Run.

**Tech Stack:** Vite, TypeScript, Canvas/DOM/SVG, Matter.js, Three.js, Vitest, Playwright.

**Spec:** User master prompt; ARCHITECTURE.md; individual game SPEC.md files.

## Global constraints

Exactly the named twelve games; screenshot-based shell; no economy, ads, accounts, tracking, backend or runtime external requests. Root and repository-subpath deployment. Original local art. Sound off by default. Truthful storage and offline limitations. Each game specialist uses GPT‑6.1 Sol and independently discovers skills.

## Review focus

- Rapid route changes must dispose late async mounts.
- Pointer scaling must match ghost placement and game coordinates.
- Restoring malformed, won or lost states must remain safe.
- Blocked storage must permit play with truthful retention status.
- Offline chunks and relative URLs must work under a subpath.
