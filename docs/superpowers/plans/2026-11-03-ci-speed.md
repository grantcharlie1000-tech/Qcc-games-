# CI under ten minutes implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Reduce expected PR CI wall time below ten minutes while preserving every existing check.

**Architecture:** Eight shards per browser run two complementary native partitions (Blockcraft and the remaining tests), each with two workers and test-level parallelism on standard GitHub runners. Browser-specific aggregate checks retain the existing required names and merge blob reports. A shared action caches npm downloads and browser binaries. Build once and share dist with parallel update/offline audits; the existing build check aggregates those audits and the separate unit/native checks.

**Tech Stack:** GitHub Actions, Node 22, npm ci, Playwright 1.64.1, Vite.

**Spec:** `/workspace/codex-briefs/ci-speed.md`.

## Review Focus

- A failed, cancelled, timed-out or skipped shard must never produce a successful aggregate for its browser.
- Chromium failure must not misreport WebKit failure, or vice versa.
- All original test IDs must occur exactly once across each browser's shards.
- Browser cache keys must change with the installed Playwright version; OS dependencies must still be installed on cache hits.
- Source interception and development-only game hooks require the existing dev server; sharing a production build would change coverage.
