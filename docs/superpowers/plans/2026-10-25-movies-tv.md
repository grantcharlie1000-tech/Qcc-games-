# Movies & TV implementation plan

Goal: deliver the requested cinematic discovery experience without disclosing any visitor activity to playback providers.
Architecture: a lazy, hash-routed TypeScript section in the existing shell; static same-origin catalog, artwork and optional licensed media; no runtime upstream APIs. Game catalog and persistence APIs remain unchanged.

- [x] Add validated catalog, local-only preferences and a fail-closed licensed-media resolver, with unit tests.
- [x] Add the full-width launch card, animated fullscreen route, browse/search/genres/list/details/seasons/episodes/player, focus/scroll restoration and Study Mode lifecycle.
- [x] Add an operator-only TMDB snapshot importer and explicit media-rights registry. Keep FrameXTV absent from executable code.
- [x] Exclude movie data/art/media from game offline downloads and runtime worker caching. Harden CSP without disrupting optional game multiplayer.
- [ ] Run unit, integration, browser, offline and build verification; independently review the change; document exact limitations and open a PR without deployment.

Review focus: blocked storage; malformed catalog and media URLs; deep links and browser Back; Study while playing; root and repository-subpath hosting; offline worker requests; keyboard/mobile access; unavailable media and network errors. No live trending claims for starter data; no invented ratings. TMDB credentials and approved attribution assets are operator inputs. No approved playback assets are currently supplied.
