## Timing checkpoint and unresolved smooth-movement acceptance

The parent’s exact steering was: “Prefer responsive truthful collision feedback over preserving a delayed visual model; do not silently change grid timing or input rules.” The coordinator selected authoritative geometry from the concrete options in response to that priority and reported its discrete-travel consequence in commentary. The selected local checkpoint displays **all head/body geometry from the authoritative grid immediately on each tick**, retaining only non-displacing food/head/face effects. There is no added visual arrival offset, and cell travel is **discrete**. `model.ts`, fixed 160 ms timing, arbitrary mid-tick buffered input and collision rules remain unchanged. Older prototype history metadata is accepted without using it to move the display backward.

The options reported before that decision were: retain continuous committed-edge projection with its one-interval offset; use authoritative discrete cell positions with cosmetics; or predict the next endpoint, which cannot satisfy unchanged mid-tick turn semantics without retarget snaps, early input locking or altered timing. The third option was rejected by the existing constraints. Commit `89b4dee` and its evidence preserve the previous continuous prototype; current documentation does not claim full continuous cell travel. The parent subsequently clarified that this discrete checkpoint improves correctness but does not meet the smooth-movement goal; it must remain local and unaccepted for that goal. No additional architecture change is authorized without a new direction.
