# Skill usage: Femboy Frosthop

Skills loaded in this session (Claude copies in `.claude/skills/`, canonical copies in `.agents/skills/`; the voxel skill is a user-level skill):

| Skill | Influence |
| --- | --- |
| using-superpowers | Session workflow: a skill check before each phase. |
| brainstorming | The user supplied a complete design pack and asked to "make and implement", so the questions were skipped. Choices the pack left open are recorded in SPEC.md as my calls. |
| game-development (router) and `3d-games` | Fixed-step simulation with interpolated rendering; simple box colliders behind richer visuals; batching and culling before other optimisations. |
| test-driven-development | Controller, course, progress and trial tests were written first and watched failing (missing modules), then implemented. Two real bugs were caught this way: springs didn't fire when walked onto, and the autopilot couldn't advance on springs. |
| voxel-artist-loop | The poster was commissioned from an artist subagent with the concept images as the reference. It ran 12 render–look–compare rounds; I reviewed the final render myself, at full size and beside other posters, before committing it. |
| systematic-debugging | Used for failures found in the browser: the frame clock reset every frame; overlays had `opacity: 0` from the dialog-only `ui-glass-sheet` class (found by measuring computed style, not by guessing); and the trial result was correctly refused after a test teleport skipped checkpoints. |
| requesting-code-review | Independent review of the full diff before completion; findings and fixes are listed in TEST_RESULTS.md. |
| verification-before-completion | No claim is made without the command output recorded in TEST_RESULTS.md. |

Not used: the Phaser skills (Three.js, not Phaser), multiplayer, and the svg-skill for hand-written SVG (the poster is generated by the shared voxel generator and checked by its validator and `tests/core/posters.test.ts`).
